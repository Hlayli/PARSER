# PARSER — база организаций для локальных продаж

PARSER собирает организации из карт и справочников, складывает их в SQLite и
даёт удобный интерфейс для обзвона: статусы, избранное, заметки, источники,
факты с сайтов. Проект рассчитан на малый бизнес и агентства, которые продают
сайты, локальное SEO и услуги продвижения.

Главный принцип: **нет выдуманным данным**. Если источник не вернул телефон —
телефона нет. Если факт взят со страницы сайта — у него есть `source_url` и
дата. Демо-записи всегда помечены.

## Возможности

- Источники: Google Maps, Яндекс.Карты, 2ГИС (API и браузерный режим), демо.
- 163 ниши в меню «Что ищем»: переключатели, поиск, «Хиты» и свой запрос.
- Сканирование области сеткой квадратов с ограничением параллелизма.
- Несколько категорий за один запуск: каждая ниша проходит по всей сетке.
- Дедупликация по телефону, затем по названию + расстоянию.
- SSE-события: прогресс ячеек и новые лиды в реальном времени.
- Карточка лида: контакты, рейтинг, часы, фото, факты с сайта.
- Продажная карточка: потенциал, зацепки, оффер, готовое сообщение и аудит сайта.
- Обогащение из сохранённых источников и с сайта: телефоны, email, соцсети, часы, адреса, рейтинг.
- Опциональный ИИ для сообщения (любой OpenAI-совместимый API); без ключа — шаблон.
- Статусы: `new`, `in_progress`, `called`, `rejected`; избранное и заметки.
- Обогащение с сайта: email, телефон, цены, соцсети, ИНН, директор, фото.
- Тёмный офлайн-интерфейс без сборки и CDN.

## Архитектура

```
 Google API ─┐
 Яндекс     ─┼─> адаптеры ──> сканер сеткой ──> SQLite ──> FastAPI ──> SSE ──> UI
 2ГИС API   ─┤   Adapter      квадраты, 3       business     /api/*     EventSource
 2ГИС браузер┤   search()     параллельно       business_    JSON
 Демо       ─┘                 лимит на ячейку   source, fact
                                    │
                              enrichment.py
                       source_facts.py — контакты из payload
                       site_audit.py   — аудит HTML
                       intel.py        — потенциал, оффер, сообщение
                                    │
                                 ai.py (опционально)
```

- **Адаптеры** приводят ответ источника к `Place` и ничего не додумывают.
- **Сканер** режет bbox на квадраты `cell_deg`, запускает до 3 ячеек
  одновременно и публикует события `cell`, `lead`, `job`, `error`.
  Источники без поддержки bbox (2ГИС) идут параллельно с квадратами, чтобы
  не задерживать Google и Яндекс.
- **SQLite** хранит организации, привязки к источникам, точки, факты и задания.
- **Обогащение** сначала читает сохранённые payload'ы 2ГИС/Яндекса (работает
  даже без сайта), затем обходит сайт и сохраняет технический аудит.
- **Аналитика карточки** (`intel.py`) считается на чтении и не ходит в сеть:
  оценка потенциала, зацепки, оффер, контакты и шаблон сообщения.
- **FastAPI** отдаёт REST, статику и `text/event-stream`.
- **UI** слушает SSE через `EventSource` и перерисовывает список и сетку.

## Установка

Нужен только Python: без SQLAlchemy, без npm, без сборки и Docker.

| Что | Требование |
|---|---|
| Python | **3.10+** (автор проверяет на 3.14) |
| ОС | Windows 10/11, macOS, Linux |
| Интернет | только для первой установки зависимостей |
| Внешние парсеры Google/Яндекс/2ГИС | не обязательны: без них работает демо-режим |

Порядок на чистой машине:

1. Установите Python 3.10 или новее с https://www.python.org/downloads/.
   На Windows при установке отметьте галочку **Add python.exe to PATH**.
2. Распакуйте папку `PARSER` целиком. Путь с пробелами и кириллицей
   допустим: лаунчеры сами переходят в свою папку.
3. Запустите лаунчер (`run.bat` на Windows, `bash run.sh` на macOS/Linux).
   При первом запуске он проверит зависимости и при необходимости выполнит
   `pip install -r requirements.txt`.
4. Дождитесь в консоли строки `Uvicorn running on http://127.0.0.1:8777`.
5. Откройте показанный адрес. Windows-лаунчер открывает браузер сам;
   проверка сервера — `http://127.0.0.1:8777/api/health`.

Виртуальное окружение не обязательно, но удобно: если рядом есть `.venv`,
лаунчеры используют его автоматически.

Windows:

```bat
py -3 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

macOS/Linux:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Активация не нужна, если вызывать интерпретатор напрямую:
`.venv\Scripts\python.exe -m pip ...` (Windows) или
`.venv/bin/python -m pip ...` (macOS/Linux). В PowerShell окружение
активируется через `.venv\Scripts\Activate.ps1`.

Переменные окружения можно задать в `.env` (читается при старте) или в системе.

## Запуск

| ОС | Обычный режим | Демо-режим |
|---|---|---|
| Windows | `run.bat` | `run_demo.bat` |
| macOS/Linux | `bash run.sh` | `bash run.sh --demo` |

Демо-режим (`PARSER_DEMO=1`) добавляет источник `demo`: приложение
открывается и работает без внешних парсеров, записи помечены «ДЕМО».
База по умолчанию одна и та же — `data/parser.db`; путь переопределяется
`PARSER_DB`.

Лаунчеры сами выбирают интерпретатор: `.venv\Scripts\python.exe` (Windows)
или `.venv/bin/python` (macOS/Linux), иначе `python3`/`python`, а
`run.bat` / `run_demo.bat` — ещё и `py -3`; сломанные заглушки пропускаются.
Если зависимостей нет, они ставятся из `requirements.txt`. Порт и адрес
берутся из `PARSER_PORT` / `PARSER_HOST` (по умолчанию `127.0.0.1:8777`) или
из `.env`; `python -m backend` читает те же переменные.

Без лаунчеров: `python -m backend` или
`python -m uvicorn backend.app:app --host 127.0.0.1 --port 8777`.
`run.bat` открывает `http://127.0.0.1:8777`; `python -m backend.app` сам сервер
не запускает — используйте `python -m backend`.

## Что отправить другу

Отправляйте всю папку `PARSER` целиком, но **не** отправляйте:

- `.venv` — окружение привязано к машине и версии Python; на новом ПК
  лаунчер возьмёт системный Python и поставит зависимости;
- `__pycache__` и `*.pyc` — кэш байткода;
- `.git` — история репозитория, если она не нужна;
- `.env` — там могут быть личные пути и ключи; вместо него отправьте
  `.env.example`.

`data/` тоже лучше не отправлять: пустая база `data/parser.db` создаётся при
первом запуске. Если базу нужно перенести, сначала остановите сервер
(Ctrl+C), затем копируйте `parser.db`, `parser.db-wal` и `parser.db-shm`
вместе — иначе последние записи потеряются.

Внешние парсеры из `parsers/` нужны только для реальных источников; для демо
их можно не отправлять.

## Если ничего не открылось

1. **Окно закрылось сразу или «python не найден».** Python не установлен
   либо не добавлен в PATH. Установите 3.10+ с python.org, отметьте
   «Add python.exe to PATH», откройте новое окно cmd и проверьте
   `python --version` или `py -3 --version`.
2. **`ModuleNotFoundError: No module named ...`** Лаунчер не смог поставить
   зависимости. Установите вручную:
   Windows — `.venv\Scripts\python.exe -m pip install -r requirements.txt`
   (или `py -3 -m pip install -r requirements.txt`);
   macOS/Linux — `.venv/bin/python -m pip install -r requirements.txt`
   (или `python3 -m pip install -r requirements.txt`). Частая причина — нет
   интернета или мешает прокси.
3. **Порт 8777 занят** (`address already in use`, `[Errno 10048]`). Задайте
   другой порт в `.env` (`PARSER_PORT=8788`) или в командной строке:
   `set PARSER_PORT=8788` перед `run.bat` (Windows),
   `PARSER_PORT=8788 bash run.sh` (macOS/Linux). Кто занял порт:
   `netstat -ano | findstr :8777` (Windows).
4. **Брандмауэр просит разрешение.** Для локальной работы достаточно
   разрешить доступ в частных сетях. По умолчанию сервер слушает только
   `127.0.0.1` и из интернета недоступен.
5. **Источники серые или «недоступен».** Без внешних парсеров это нормально:
   Google/Яндекс/2ГИС требуют своих утилит. Проверьте пути в `.env`
   (`GMSC_PATH`, `YAMAPS_DIR`, `TWOGIS_DIR`) или запустите демо-режим.
6. **Проверка сервера.** Откройте `http://127.0.0.1:8777/api/health` —
   должен вернуться JSON с `"ok": true`, списком адаптеров и причиной
   недоступности каждого. В консоли должна быть строка
   `Uvicorn running on ...`.
7. **Браузер не открылся сам.** Откройте адрес из консоли вручную;
   на macOS/Linux лаунчер браузер не запускает.

GitHub Pages для этого проекта не подходит: Pages отдаёт только статические

Чтобы работать со своими лидами, перетащите `data/parser.db` в папку `data`

Ограничения облака: парсеры Google (`gmsc.exe`), Яндекс (локальный Windows-venv)

Бесплатный лимит Codespaces для личного аккаунта: 120 core-часов и 15 ГБ
хранилища в месяц; codespace останавливается после 30 минут простоя.

## Быстрый старт

1. Запустите `run_demo.bat` / `run.bat` (Windows) или `bash run.sh --demo` /
   `bash run.sh` (macOS/Linux) и откройте `http://127.0.0.1:8777`.
2. Нажмите «Что ищем» и включите нужные ниши: по умолчанию выбраны
   стоматологии, шиномонтаж и кофейни. Можно нажать «Хиты», «Все» или
   «Сбросить», найти нишу поиском либо добавить свой запрос в поле ниже.
3. Укажите город и нажмите «Начать сканирование»: слева пойдёт сетка, в центре
   появятся лиды. Категории сканируются по очереди, по всем квадратам.
4. Отмечайте карточки: `★` избранное, `☎` отзвонено, `⚙` в работе, `✕` отказ;
   откройте карточку, чтобы увидеть факты, источники и запустить обогащение.
5. Долгий скан можно остановить кнопкой «Стоп» — найденные лиды сохранятся.
6. Демо-записи идут с префиксом «ДЕМО — » и не являются реальными бизнесами.

## Как работает сканирование квадратами

`bbox` задаётся как `(min_lon, min_lat, max_lon, max_lat)` в WGS84.
`cell_deg` — размер стороны квадрата в градусах (по умолчанию `0.05`).
Сканер делит область на `nx × ny` ячеек, но не более 2000 ячеек: при
превышении шаг автоматически укрупняется.

По каждой ячейке вызывается `adapter.search(query, cell_bbox, limit)`, не более
3 ячеек одновременно. Это даёт равномерное покрытие: API отдаёт 50–60
результатов на запрос, поэтому один большой bbox терял бы плотную застройку.

Выбранные категории превращаются в список поисковых запросов. Для каждой
категории сканер заново проходит всю сетку: сначала квадраты, затем следующий
запрос. Поэтому в интерфейсе видно «Категория 2 из 5», а сетка сбрасывается на
каждом проходе. Найденные лиды не удаляются между проходами. Например, 2 ниши
на Тюмень при `0.05` — это 2 запроса × 66 квадратов = 132 запроса на источник;
Google и Яндекс идут по квадратам, 2ГИС обходит город один раз на категорию.
Больше 24 категорий интерфейс помечает как долгий скан, максимум — 300
запросов за запуск.

Google ищет от центра ячейки с радиусом, рассчитанным по её диагонали, а затем
адаптер дополнительно отбрасывает точки за пределами квадрата (с запасом 10 %):
`-radius` у gmsc не является строгим. Яндекс получает bbox ячейки напрямую.
2ГИС не умеет bbox и обходит город целиком, поэтому запускается параллельно с
квадратами, а результаты фильтруются по bbox задания. Город для 2ГИС берётся из
поля `city` запроса, иначе из `TWOGIS_CITY`; название транслитерируется в slug
(`Тюмень` → `tyumen`).

События SSE: `hello`, `cell` (статус и число найденных), `lead` (`is_new`),
`job` (прогресс) и `error` (ошибка источника с причиной).

## Фотографии

Фото берутся только из реальных источников:

- Google — поле `thumbnail` (реальное изображение места; массив `images` в
  gmsc 1.18.x обычно пуст);
- сайт бизнеса — `og:image`, `twitter:image` и крупные `<img>` (от 400 px);
- 2ГИС — фото не отдаёт, страница организации закрыта заглушкой для ботов.

Варианты одного и того же файла через imgproxy/ресайзер схлопываются по
исходному URL. Хранится не больше 12 фото на организацию. Если фото нет — блок
скрывается, заглушки не подставляются.

## Дедупликация и сети

Одна и та же организация у Google, Яндекса и 2ГИС может стоять в разных
точках карты, называться «SwipeCoffee» и «Swipe Coffee», а адрес приходить как
«Рязань, район Приокский, Дачная улица, 5» или «Дачная улица, 5». Поэтому
координаты — только один из сигналов, и самый слабый.

Порядок в `db.upsert_place` (`backend/dedup.py`):

1. Та же запись источника (`source` + `source_id`).
2. **Сеть** — `brand_key`: нормализованное название без пробелов и оргформ,
   без родовых слов («Кофейня», «Кафе», «Coffee» и т.п.). Одна сеть — одна
   карточка, даже если точки в разных районах.
3. **Та же точка** — сравнение по совокупности: телефон, адрес (улица + дом),
   сайт, название и расстояние. Сильный телефон (кроме 8-800), совпадение
   адреса или название + близость дают склейку; разные дома — стоп-сигнал.
4. Демо-записи никогда не склеиваются с реальными.

При совпадении пустые поля дозаполняются, существующие не перезаписываются,
привязка к источнику добавляется в `business_source`, а адрес и телефон
конкретной точки — в `business_location`. В карточке видно все источники,
`locations_count` и список «Точки сети»; у сетей на карточке бейдж
`сеть · N`.

Родовые названия не считаются брендом: две «Кофейни» на разных улицах —
две карточки. 8-800 — общий номер сети, по нему точки не склеиваются;
номера из 18 цифр (склейка 8-800 с добавочным в 2ГИС) отбрасываются.

Склейка уже накопленной базы (с резервной копией рядом с файлом БД):

```bat
cd PARSER
python -m backend.merge_duplicates           :: только отчёт
python -m backend.merge_duplicates --apply   :: склеить
```

Перед изменением создаётся `data/parser.db.bak-<дата>-<время>` через SQLite
backup API. Склейка переносит статусы, избранное, заметки, факты, фото,
источники и точки в оставшуюся карточку.

## Принцип «нет выдуманным данным»

- `Place` содержит только поля, которые реально вернул источник.
- Нет данных → пустая строка или `None`; UI пишет «нет данных».
- Каждый факт (`email`, `phone`, `price`, `photo`, `social`, `director`,
  `description`, `inn`, `hours`, `address`) хранится с `source_url` и
  `fetched_at`. Без URL факт не создаётся.
- `director` пишется только при явном ФИО рядом с должностью; `price` — только
  при явной сумме; email не угадывается по шаблону.
- `is_demo=1` и имя «ДЕМО — …» отделяют тестовые записи от реальных.
- `has_site` — вычисляемый признак: `bool(website)`, а не отдельное поле.

## API (кратко)

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | статус, список адаптеров, демо-флаг и настройка ИИ (`ai`) |
| `GET` | `/api/categories` | каталог ниш: группы, наборы по умолчанию и «Хиты» |
| `POST` | `/api/scan/estimate` | объём скана: запросы × квадраты |
| `POST` | `/api/scan` | запуск сканирования (категории и/или свой запрос) |
| `GET` | `/api/jobs`, `/api/jobs/{id}` | задания и ячейки |
| `POST` | `/api/jobs/{id}/pause\|resume\|stop` | управление |
| `GET` | `/api/leads` | список с фильтрами (`status`, `source`, `q`, `fav`, `site=no\|yes`) и пагинацией |
| `GET` | `/api/leads/{id}` | полная карточка + факты + `locations` + `site_audit` + `intel` |
| `PATCH` | `/api/leads/{id}` | статус, избранное, заметка |
| `POST` | `/api/leads/{id}/enrich` | контакты из источников + обход сайта + аудит |
| `POST` | `/api/leads/{id}/pitch` | сообщение для первого контакта: ИИ или шаблон |
| `GET` | `/api/stats` | сводка |
| `GET` | `/api/events` | SSE-поток |

`GET /api/leads/{id}` дополнительно отдаёт `site_audit` (HTTPS, мобильность,
формы, CMS) и `intel` — оценку потенциала, зацепки, оффер, контакты и шаблон
сообщения. Всё это считается только по данным карточки, без сетевых запросов.

`POST /api/leads/{id}/enrich` возвращает `status` (`ok`, `no_site`,
`social_only`, `error`), `message`, `added`, `errors`, `site_audit` и полную
`lead`. Для бизнеса без сайта это не ошибка: сначала собираются контакты из
сохранённых payload'ов 2ГИС/Яндекса.

`POST /api/leads/{id}/pitch` возвращает `{ok, source: "ai"|"template", text,
model, error}`. Без ключа или при сбое ИИ `source` равен `template`, а `text`
содержит готовое сообщение из карточки.

Наличие сайта не фильтруется при сборе: источники отдают все организации,
а решение принимается при работе с базой. В карточке есть `has_site`,
в `/api/stats` — `with_site`/`no_site`, в выдаче — фильтр `site=no|yes`
(в интерфейсе — «Без сайта» / «С сайтом»). Поэтому лиды без сайта не теряются,
и можно отдельно работать с теми, кому сайт нужен.

## Тесты

```bat
cd PARSER
python -m unittest discover tests -v
```

Тесты создают временную БД через `PARSER_DB` и не трогают `data/parser.db`.
`test_core` проверяет вставку, дедупликацию, статусы, статистику, факты и
каталог категорий. `test_api` — health, 404, валидацию, оценку объёма и
демо-сканирование крошечного bbox. `test_intel`, `test_site_audit`,
`test_source_facts` и `test_ai` проверяют продажную логику, аудит HTML,
разбор payload'ов и ИИ-клиент без сети. `test_integration` — `intel` в
карточке, заполнение из payload'ов, восстановление адресов Яндекса, сценарии
`no_site`/`social_only` и шаблонный ответ `/pitch` без ключа.

## Ограничения и юридический раздел

- **ToS карт.** Автоматический сбор данных Google Maps, Яндекс.Карт и 2ГИС
  может нарушать пользовательские соглашения. Google прямо запрещает
  scraping и хранение контента вне сервиса; Яндекс продаёт право хранения
  отдельной лицензией; 2ГИС требует разрешений на контактные поля. Перед
  промышленным использованием согласуйте лицензию с правообладателем.
- **Персональные данные.** Телефоны, email и ФИО — персональные данные.
  В РФ действует 152-ФЗ: общедоступные справочники создаются с письменного
  согласия, субъект вправе потребовать исключения. В ЕС — GDPR: нужна
  законная основа (например, законный интерес), уведомление субъекта и
  возможность удаления. «Данные опубликованы» не означает «можно делать с
  ними что угодно».
- **Ответственность.** Ответственность за использование собранных данных,
  рассылки и хранение лежит на операторе. Массовые рекламные рассылки в РФ
  регулируются 38-ФЗ и требуют согласия.
- **Технические ограничения.** CAPTCHA и авторизацию не обходим; соблюдаем
  задержки; не логируем персональные данные; не выдаём демо за реальные.
- **Качество.** API меняют поля и лимиты, селекторы браузерных источников
  ломаются; ошибки видны в SSE `error` и в статусе ячейки.

## Как добавить новый источник

1. Создайте `backend/adapters/my.py`, унаследуйте `Adapter` из
   `backend/adapters/base.py`, задайте `name`, `label`, `supports_bbox`.
2. Реализуйте `available() -> (bool, reason)`: проверка ключа, бинарника или
   доступности сети.
3. Реализуйте `async def search(query, bbox, limit) -> list[Place]`:
   - заполняйте только реальные поля;
   - `source_id` обязателен и стабилен;
   - сетевые/парсинговые ошибки → `AdapterError` с причиной;
   - таймаут на весь поиск — не более 120 секунд;
   - `raw` — только ответ источника.
4. Зарегистрируйте адаптер в `backend/adapters/registry.py` (`all_adapters()`).
5. Добавьте источник в UI, если он должен быть доступен для выбора.
6. Добавьте тест на нормализацию и на отсутствие выдуманных полей.

Не добавляйте зависимости вне `requirements.txt` и не пишите в чужие файлы.
