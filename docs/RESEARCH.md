# RESEARCH — поиск и обогащение базы организаций

Дата: 12.11.2026. Автор: группа «Документация и качество».

Легенда:
- **[ДОК]** — проверено по указанному источнику (документация, тарифы, закон).
- **[ОБЩ]** — общеизвестно или экспертная оценка; первоисточник не проверялся.

Цель исследования — понять, как легально получать данные об организациях, где
проходят границы API, зачем нужен браузерный fallback и какие требования
предъявляются к персональным данным.

## 0. Выводы для PARSER

1. Все три картографических API закрывают базовые поля (название, адрес,
   координаты, телефон, сайт, рейтинг), но различаются ценами, лимитами и
   правами на хранение данных. [ДОК]
2. Google прямо запрещает выгружать и хранить контент вне сервиса, кроме
   `place_id` (и координат на срок до 30 дней). Постоянная база лидов на Google
   возможна только по отдельной лицензии. [ДОК]
3. Яндекс продаёт право на сохранение и изменение данных в «Расширенной»
   лицензии; стандартная лицензия такого права не даёт. [ДОК]
4. 2ГИС требует отдельного разрешения на контактные поля и часть методов. [ДОК]
5. Браузерный парсинг — fallback на случай отсутствия ключа/бюджета и для
   источников, где API не отдаёт нужные поля. Он не отменяет ToS и 152-ФЗ. [ОБЩ]
6. Для PARSER критичны: `source_url` + `fetched_at` у каждого факта, отсутствие
   выдуманных полей, демо-маркировка и возможность удалить данные по запросу.
   Это соответствует духу 152-ФЗ и GDPR. [ОБЩ]

## 1. Google Places API (New): Text Search

### Устройство и лимиты [ДОК]

- Endpoint: `POST https://places.googleapis.com/v1/places:searchText`.
- Запрос обязан содержать `X-Goog-FieldMask`; без маски — ошибка.
- `pageSize` — от 1 до 20; всего Text Search отдаёт **не более 60 результатов**
  по всем страницам.
- `locationRestriction` — только прямоугольник и только для категорийных
  запросов; `locationBias` — прямоугольник или круг радиусом до 50 000 м.
- Результаты не гарантированно стабильны между одинаковыми запросами.
- Есть `nextPageToken`; параметры всех страниц, кроме `pageSize`/`pageToken`,
  должны совпадать.

### Поля, которые нужны PARSER [ДОК]

| Поле API | Что даёт | SKU |
|---|---|---|
| `places.id` | стабильный ID | Essentials (IDs only) |
| `places.displayName` | название | Pro |
| `places.formattedAddress`, `places.location` | адрес, координаты | Pro |
| `places.photos` | фото | Pro |
| `places.nationalPhoneNumber`, `places.internationalPhoneNumber` | телефон | Enterprise |
| `places.websiteUri` | сайт | Enterprise |
| `places.rating`, `places.userRatingCount` | рейтинг, число отзывов | Enterprise |
| `places.regularOpeningHours` | часы | Enterprise |
| `places.priceLevel`, `places.priceRange` | ценовой диапазон | Enterprise |

Практический вывод: запрос телефона, сайта и рейтинга переводит вызов в
**Text Search Enterprise**, даже если остальные поля из Pro. [ДОК]

### Цены (глобальный прайс, USD за 1000 событий) [ДОК]

- Text Search Essentials (IDs only) — бесплатно, без лимита.
- Text Search Pro — $32 после 5 000 бесплатных событий в месяц.
- Text Search Enterprise — $35 после 1 000 бесплатных событий в месяц.
- Дальше действуют скидки за объём: например, $28 на диапазоне
  100 001–500 000 событий.
- Цены и бесплатные лимиты могут меняться; перед расчётом бюджета проверять
  актуальный прайс Google.

### Хранение, кэширование, скрейпинг [ДОК]

Политика Places API (New) прямо запрещает:
- кэшировать/хранить контент Google Maps иначе, чем разрешено Service Specific
  Terms;
- выгружать, извлекать или скрейпить контент, в том числе массово скачивать
  названия, адреса и отзывы;
- создавать производный контент на основе данных Google.

Исключения:
- `place_id` можно хранить бессрочно;
- широту/долготу — временно, не более 30 календарных дней (для перечисленных
  сервисов, включая Places API).

Также обязательна атрибуция «Google Maps» и соблюдение требований к фото и
отзывам. Вывод: PARSER не должен строить долговременную базу на Google без
отдельного договора; в коде это надо явно документировать. [ДОК]

## 2. 2ГИС Places API

### Устройство [ДОК]

- Endpoint: `GET https://catalog.api.2gis.com/3.0/items`.
- Параметры: `q`, `location=lon,lat`, `radius` (0–50 000 м при наличии `q`,
  иначе 0–2 000 м), `point1`/`point2` (прямоугольник; без `q` расстояние между
  точками не более 2 км), `polygon` (WKT, площадь ~6 км²), `page_size` до 50,
  `page` до 1 000 000.
- Поиск идёт только по активным (работающим) объектам.
- Ответ: `meta.code`, `result.items`, `result.total`.
- Базовые поля: `id`, `name`, `address_name`, `type`.
- Дополнительные поля запрашиваются через `fields`: `items.point`,
  `items.address`, `items.rubrics`, `items.schedule`, `items.reviews`,
  `items.contact_groups` и др.
- `items.contact_groups`, `items.itin`, `items.trade_license`, `items.fias_code`
  и ряд других полей **требуют дополнительного разрешения ключа**. [ДОК]
- Методы `bysite`, `byphone`, `byitin` — отдельная платная опция. [ДОК]

### Лимиты и цены [ДОК]

- Успешный запрос — HTTP 200/204 (в теле `meta.code`).
- Для подписки: 600 запросов в минуту на Places API (фиксированный лимит).
- Демо-ключ: 1 000 запросов к Places API.
- Стоимость — пакетами за расчётный месяц; на странице тарифов пакеты Places API
  идут от 6 700 ₽ до 250 000 ₽. Точное число запросов в пакете зависит от
  выбранного объёма и проверяется в кабинете.
- Годовая оплата даёт скидку 10%.

## 3. Яндекс «Поиск по организациям» (Geosearch)

### Возможности [ДОК]

- База: 13 млн действующих организаций в России, СНГ и Турции, обновляется
  ежедневно.
- Поиск по названию, адресу, телефону, услугам, категориям.
- В ответе — до **50 объектов**, отсортированных по релевантности.
- Доступ по HTTPS, а также через JS API и MapKit.
- Поля: тип деятельности, адрес, часы работы, контакты.

### Цены и права [ДОК]

| Лицензия | Запросов в сутки | Цена в год | Сверх лимита |
|---|---|---|---|
| Стандартная | до 1 000 | 195 000 ₽ | 390 ₽ / 1000 |
| Расширенная | до 1 000 | 226 200 ₽ | 390 ₽ / 1000 |

- Более высокие тарифы: 10 000, 25 000, 50 000, 100 000 запросов в сутки;
  цены от 585 000 ₽ до 2 184 000 ₽ в год (стандартная лицензия).
- В таблице тарифов у «Расширенной» лицензии отмечено право
  **«Сохранение и изменение данных»**; у стандартной такой отметки нет.
  Для PARSER это принципиально: хранить базу лидов можно только при наличии
  соответствующего права. [ДОК]

## 4. Рынок local lead generation

- По данным Google (в пересказе Ahrefs): 30% мобильных поисков связаны с
  локацией; 78% людей, ищущих «рядом» на телефоне, посещают бизнес в течение
  дня; 28% таких поисков заканчиваются покупкой. [ДОК, вторичный источник]
- Google (в пересказе Ahrefs): у бизнесов с заполненным Business Profile на 70%
  выше вероятность визита и на 50% — вероятность покупки. [ДОК, вторичный]
- По опросу BrightLocal (цитируется Ahrefs): 36% SEO-специалистов считают
  Google Business Profile главным фактором Map Pack; 17% — отзывы. [ДОК,
  вторичный]
- Типичная услуга агентства: сайт + карточка в справочниках + локальное SEO +
  сбор отзывов. База организаций без сайта — сырьё для продажи этих услуг.
  [ОБЩ]
- Ниша «сайты для малого бизнеса» конкурентна; дифференциация — в свежести
  контактов, наличии телефона/сайта и удобном обзвоне. [ОБЩ]

## 5. Зачем браузерный парсинг как fallback

Причины:
- API платные, требуют ключа и юридически ограничивают хранение. [ДОК]
- API отдают 50–60 результатов на запрос; для плотной городской застройки
  нужна сетка квадратов. [ДОК]
- Часть полей (контакты, ИНН, соцсети) в API закрыта дополнительным
  разрешением или отсутствует. [ДОК]
- У малого бизнеса может не быть сайта, но карточка в справочнике есть. [ОБЩ]

Ограничения fallback:
- ToS карт могут запрещать автоматический сбор; для Google это прямой запрет
  на scraping. [ДОК]
- CAPTCHA, авторизация, обход защит — недопустимы. [ОБЩ]
- Динамическая вёрстка и смена DOM ломают парсер; нужны селекторы с запасом и
  мониторинг ошибок. [ОБЩ]
- Нагрузку надо ограничивать: задержки, лимит страниц, уважение `robots.txt`.
  [ОБЩ]
- Каждый факт должен иметь `source_url` и время; иначе данные невозможно
  проверить и удалить. [ОБЩ]

Позиция PARSER: API — основной путь; браузерный адаптер — только для
источников, где это разрешено, и с явной пометкой источника. Google Maps
браузером не скрейпим. [ОБЩ, решение проекта]

## 6. Персональные данные

### 152-ФЗ (РФ)

- Ст. 8: общедоступные источники персональных данных (справочники, адресные
  книги) создаются с **письменного согласия** субъекта; в них могут включаться
  ФИО, год и место рождения, адрес, абонентский номер, профессия и иные данные.
  По требованию субъекта сведения должны быть исключены в любое время. [ДОК]
- Ст. 6: обработка допустима только при наличии основания (согласие, договор,
  закон, законные интересы и др.). [ДОК]
- Практика: «данные есть в открытом справочнике» не равно «можно делать с ними
  что угодно». Для базы лидов нужны цель, основание, минимизация, срок
  хранения и процедура удаления. [ОБЩ]
- Закон не даёт универсального «B2B-исключения»: ИП и контактные лица —
  субъекты персональных данных. [ОБЩ]

### GDPR (ЕС)

- Ст. 6(1)(f): законный интерес контролёра или третьей стороны — возможное
  основание для B2B-контактов, если интересы субъекта не перевешивают;
  нужна оценка баланса интересов (LIA). [ДОК]
- Ст. 14: если данные получены не от субъекта, ему нужно сообщить сведения о
  контролёре, целях, основании, категориях данных, источнике и правах —
  в разумный срок, но не позднее одного месяца. [ДОК]
- Права: доступ, исправление, удаление (ст. 17), возражение против обработки
  (ст. 21), ограничение обработки. [ОБЩ]
- Для PARSER: хранить источник и дату получения, иметь канал для запросов на
  удаление, не собирать специальные категории данных. [ОБЩ]

### Что это значит для продукта

1. В карточке лида — только деловые контакты, без личных данных «на всякий
   случай».
2. `fact` хранит `source_url` и `fetched_at`; без источника факт не создаётся.
3. Демо-данные помечены `is_demo=1`, чтобы их нельзя было выдать за реальные.
4. Нужен сценарий удаления/анонимизации лида по запросу.
5. Логи не должны содержать телефоны и ФИО.
6. Юридическую политику и сроки хранения утверждает владелец продукта; этот
   документ — инженерная выжимка, а не юридическое заключение.

## 7. Практическая архитектура получения данных

1. **API-first**: Google Places, 2ГИС, Яндекс — если есть ключ и право хранить.
2. **Сетка**: bbox делится на квадраты; по каждой ячейке — запрос с лимитом
   50–60 результатов.
3. **Дедуп**: телефон → нормализованный телефон; иначе имя + расстояние
   < 250 м.
4. **Обогащение**: обход сайта, только явные факты, каждый с `source_url`.
5. **Fallback**: браузерный адаптер для разрешённых источников, с задержками и
   лимитами.
6. **Контроль качества**: пустое поле остаётся пустым; никаких «примерных»
   телефонов, рейтингов и отзывов.
