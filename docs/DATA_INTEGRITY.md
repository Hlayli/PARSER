# Политика достоверности данных

Главное требование проекта: **ни одно утверждение о бизнесе не должно быть выдумано.**
Этот документ описывает, как требование реализовано технически.

## 1. Три уровня данных

| Уровень | Откуда | Как помечен |
|---|---|---|
| **Факт источника** | ответ Google / Яндекс / 2ГИС | `business_source.payload_json` + `business.source` |
| **Факт со страницы** | HTML сайта бизнеса | `fact.source_url` = точный URL страницы |
| **Демо** | генератор | `business.is_demo = 1`, имя начинается с «ДЕМО — » |

Никакого четвёртого уровня нет. Модель не «додумывает» поля.

## 2. Правила записи

1. Поле заполняется **только** если источник вернул непустое значение.
2. Нормализация (телефон → `+7...`) не создаёт новой информации: она лишь приводит формат.
3. Обогащение с сайта сохраняет **дословный фрагмент** и URL страницы. Если фрагмент не найден — факт не создаётся.
4. `director` пишется только при совпадении регулярного выражения с реальным ФИО рядом с должностью. Совпадение по одному слову «директор» без имени игнорируется.
5. `price` — только явные числа с валютой. «Недорого», «по запросу» не считаются ценой.
6. Фото — только реальные URL из источника или со страницы; варианты одного
   файла через ресайзер схлопываются по исходному URL, хранится до 12 фото.
   Битые ссылки скрываются на клиенте, а не заменяются заглушками.
7. Дубликаты фактов схлопываются по `(kind, value)`; телефоны — по
   нормализованному номеру, фото — по каноническому URL.

## 3. Отображение

- Пустое поле → серый текст «нет данных». Не «—», не прочерк, не выдуманное значение.
- У каждого факта в карточке показывается ссылка-источник (`source_url`) и дата получения.
- В списке лидов показываются бейджи всех источников, где организация реально найдена (`business_source`).
- Демо-записи always имеют оранжевый бейдж `ДЕМО` и не смешиваются с реальными визуально.

## 4. Дедупликация и её риск

Склейка идёт по нормализованному телефону, затем по имени + расстоянию ≤ 250 м.
Склейка по имени работает только при наличии координат у обеих записей.
Риск ложной склейки существует (две точки одной сети). Поэтому:
- объединяются только пустые поля, существующие значения не перезаписываются;
- все исходные привязки сохраняются в `business_source`, так что карточку всегда можно развести обратно.

## 5. Чего система принципиально не делает

- Не генерирует описания бизнеса «нейросетью» без источника.
- Не придумывает email по шаблону `info@domain`.
- Не угадывает ФИО руководителя по названию компании.
- Не подставляет фото-заглушки.
- Не выдаёт демо-данные за реальные.

## 6. Правовая рамка

- Парсинг карт нарушает пользовательские соглашения Google, Яндекс и 2ГИС.
- Телефоны и email физических лиц — персональные данные: 152-ФЗ (РФ), GDPR (ЕС).
- Массовые рассылки регулируются 38-ФЗ «О рекламе» и требуют согласия.
- Ответственность за использование собранных данных лежит на операторе.
